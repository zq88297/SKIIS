# 跨项目/跨模块任务派发

你是任务派发器。将当前项目中发现的问题，以结构化任务的形式发送给另一个项目或模块。

## 参数

`$ARGUMENTS` 为目标路径（必填）：
- 绝对路径：`/task-send /home/user/projects/ike-module`
- 相对路径：`/task-send ../ike-module`
- 子模块名：`/task-send ike-module`（在当前项目下查找）

## 执行步骤

### Step 1：确认目标

1. 解析 `$ARGUMENTS` 获取目标路径
2. 如果未提供路径，询问用户："请提供目标项目/模块的路径？"
3. 验证目标目录存在（不存在则询问是否创建或更正）

### Step 2：收集当前上下文

自动提取当前会话中的关键信息：

- **问题描述**：当前在排查什么问题？
- **交互关系**：当前项目如何与目标项目交互？（API、socket、共享内存、消息队列...）
- **关键接口**：涉及哪些函数/接口/协议？
- **已知线索**：日志、返回值、抓包数据、异常现象
- **排查建议**：建议目标项目从哪些方向排查？

向用户展示提取的内容，确认或补充。

### Step 3：初始化目标（如需）

检查目标项目的 `.claude/context/` 目录：
- 不存在 → 自动执行规则 5（初始化上下文系统 + 安装 hooks）
- 存在但缺少 `tasks/` → 创建 `.claude/context/tasks/`

### Step 4：生成任务文件

在目标项目中创建 `.claude/context/tasks/from-{来源项目}-{日期}-{简要}.md`：

```markdown
# 来自「{来源项目}」的排查任务

> 派发时间：{datetime}
> 来源路径：{当前项目路径}
> 当前层级：{根目录 / 子模块A / 子模块A1}

## 问题背景

{当前项目遇到了什么问题，为什么怀疑目标项目}

## 交互关系

| 项目 | 说明 |
|------|------|
| 调用方式 | {API调用 / socket / 共享内存 / ...} |
| 发起方 | {当前项目的哪个模块发起调用} |
| 接收方 | {目标项目的哪个模块接收} |
| 数据流 | {A传给B什么，B返回什么} |
| 关键接口 | {函数名、参数、返回值类型} |

## 已知线索

{日志片段、错误码、返回值、抓包数据等}

## 排查建议

- [ ] {具体检查项1}
- [ ] {具体检查项2}
- [ ] {具体检查项3}

## 附加信息

{相关代码片段、配置文件、测试用例等}
```

### Step 5：更新来源项目记录

在**当前项目**的 `current-task.md` 中追加：

```markdown
📤 **已派发任务** — {datetime}
- 目标：{目标路径}
- 任务文件：{目标路径}/.claude/context/tasks/from-xxx.md
- 摘要：{一句话描述}
- 状态：等待排查
```

### Step 6：报告

```
✅ 任务已派发

📤 来源：{当前项目}（{层级}）
📥 目标：{目标项目}
📄 任务文件：.claude/context/tasks/from-{来源}-{日期}.md

目标项目下次 /session-load 时将优先展示此任务。
```
